# v0.7.7 — Feedback loops

## Theme

Capture user feedback (thumbs up / down / neutral, optional comment)
on retrieval results and answers. Wire it into retrieval via a
pluggable `FeedbackScorer` so future training loops have a clean
data source. Surface aggregate metrics through Langfuse.

This release depends on `TenantResolver` (v0.7.3) and the
`FeedbackScorer` algorithms stated in ADR `0016`.

## Breaking changes (R4 — no shims, no aliases, no deprecation)

- New `Feedback` Pydantic model added to `raghub.models`; existing
  models are unaffected.
- New endpoints:
  - `POST /v1/feedback`
  - `GET /v1/feedback`
  - `DELETE /v1/feedback/{id}`
  - `GET /v1/feedback/aggregate`
- `FeedbackStore` Protocol added; `SqliteFeedbackStore` default;
  `PgFeedbackStore` reuses the pgvector connection.
- `FeedbackScorer` Protocol added; `bm25-boost` and
  `vector-down-weight` algorithms shipped as built-in.
- New CLI: `raghub feedback export --jsonl …`,
  `raghub feedback stats --tenant …`.
- `RAG.query` accepts an optional `feedback_scorer` argument;
  default `None` (feedback loop disabled).

## Prerequisites

- `v0.7.6` is the current published release.

## ADR (must be committed before any PR)

ADR `0016-feedback-loop.md` defines:

- `bm25-boost` algorithm:
  - For a query, compute the BM25 score for each candidate
    chunk as usual.
  - For each candidate chunk with at least one positive feedback
    (`rating == 1`) in the tenant, multiply the BM25 score by
    `(1 + α * log(1 + positive_count))` where `α = 0.5`.
  - For each candidate chunk with at least one negative feedback
    (`rating == -1`) in the tenant, multiply the BM25 score by
    `(1 - β * log(1 + negative_count))` where `β = 0.3`.
  - The boosted scores are returned through the existing
    `fusion.rrf` pipeline.

- `vector-down-weight` algorithm:
  - For a query, compute the dense-similarity score as usual.
  - For each candidate chunk with negative feedback, multiply
    the similarity by `0.5` (configurable, default `0.5`).
  - Positive feedback has no effect on dense scoring in this
    algorithm.

- Both algorithms are stateless given the feedback set; the
  feedback set is loaded once per query.

## Atomic items

80. **`Feedback` Pydantic model** — `raghub/feedback/models.py`:
    ```python
    class Feedback(BaseModel):
        id: str
        session_id: str
        query_id: str
        chunk_id: str | None
        answer_id: str | None
        user_id: str
        tenant_id: str
        rating: Literal[-1, 0, 1]
        comment: str | None
        created_at: datetime
        metadata: dict[str, Any] = {}
    ```

    - `test_feedback_rating_must_be_in_set`

81. **`FeedbackStore` Protocol + `SqliteFeedbackStore`** —
    `raghub/feedback/store.py`. Protocol:
    ```python
    class FeedbackStore(Protocol):
        async def record(self, feedback: Feedback) -> None: ...
        async def get(self, feedback_id: str) -> Feedback | None: ...
        async def list_for_session(self, session_id: str) -> list[Feedback]: ...
        async def list_for_chunk(self, chunk_id: str) -> list[Feedback]: ...
        async def list_for_tenant(self, tenant_id: str, limit: int = 1000) -> list[Feedback]: ...
        async def delete(self, feedback_id: str) -> None: ...
        async def aggregate(self, tenant_id: str | None = None) -> FeedbackAggregate: ...
    ```
    `SqliteFeedbackStore` schema:
    ```sql
    CREATE TABLE IF NOT EXISTS raghub_feedback (
        id TEXT PRIMARY KEY,
        session_id TEXT NOT NULL,
        query_id TEXT NOT NULL,
        chunk_id TEXT,
        answer_id TEXT,
        user_id TEXT NOT NULL,
        tenant_id TEXT NOT NULL,
        rating INTEGER NOT NULL,
        comment TEXT,
        created_at TEXT NOT NULL,
        metadata TEXT NOT NULL DEFAULT '{}',
        UNIQUE (session_id, query_id, chunk_id, user_id)
    );
    CREATE INDEX IF NOT EXISTS raghub_feedback_tenant_chunk
        ON raghub_feedback (tenant_id, chunk_id);
    ```

    Tests:
    - `test_feedback_store_record_get_delete`
    - `test_feedback_store_list_for_tenant_filters`
    - `test_feedback_store_aggregate`

## Security review

This release introduces PII-bearing user content; the security
artefact is `docs/security/threat-models/v0.7.7-feedback.md`.

### Threat model

| Threat | Mitigation |
|---|---|
| **PII leakage via `feedback.comment`**: a user pastes a credit card number, password, or email into a comment; the system stores it. | `RedactingTelemetry.redact_record` runs at persistence; secret keys redacted before storage; test injects PII and asserts the redacted form is persisted. |
| **Cross-tenant feedback read**: a user reads another tenant's feedback via `GET /v1/feedback?tenant_id=…`. | Default filter applies the caller's `tenant_id`; admin role required for cross-tenant queries; tested. |
| **API abuse via spam feedback**: an attacker spams `POST /v1/feedback` to fill storage and DoS the system. | Per-user rate limit on `POST /v1/feedback` reuses v0.7.3 infrastructure; admin can configure a stricter rate. |
| **Tenant-id spoofing via `tenant_id` field in the body**: an attacker sends `tenant_id: "victim"` to write feedback as another tenant. | The server ignores the body's `tenant_id` and uses the `TenantResolver`-derived claim. |
| **Feedback inference attack**: an attacker with read access to the feedback DB infers sensitive user activity patterns. | Documented operator concern; access control at the storage layer is admin-only. |
| **Comment XSS when rendered in a UI**: a user injects `<script>` into a comment. | Comments stored as-is; rendering is the operator's responsibility; documented. |
| **Storage path traversal in `export --jsonl`**: a user supplies `--jsonl /etc/passwd` to overwrite system files. | The path is validated against `Settings.export.allowed_paths`; default is `Settings.data_dir` only. |

### Mitigations accepted

- PII redaction at persistence.
- Per-user rate limit.
- Tenant-id from `TenantResolver`, never from body.
- Export path validation.

### Out-of-scope

- Feedback-based re-ranking training: deferred (export JSONL is the
  integration point).
- Per-tenant feedback quotas: deferred.
