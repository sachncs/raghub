# v0.7.8 — Backup / restore

## Theme

Land a portable, version-pinned, integrity-checked backup format
(`ArchiveManifest` v1) and a `LocalArchiveStore` implementation.
Add CLI commands for backup, restore, and verify. The format is
designed so community adapters for S3 / GCS / Azure can plug in via
`PluginRegistry.register_archive_store` without changing the format.

## Breaking changes (R4 — no shims, no aliases, no deprecation)

- New `ArchiveManifest` schema with `format_version: int = 1`. Any
  prior backup taken with the ad-hoc `raghub migrate` flow is
  not migrated; v0.7.8 backups are required.
- New CLI commands: `raghub backup`, `raghub restore`,
  `raghub backup verify`.
- `LocalArchiveStore` writes a deterministic tar + `manifest.json`
  + SHA-256 checksums, zstd-compressed.

## Prerequisites

- `v0.7.7` is the current published release.

## Atomic items

89. **`ArchiveStore` Protocol + `LocalArchiveStore`** —
    `raghub/archive/store.py`:
    ```python
    class ArchiveStore(Protocol):
        async def put(self, key: str, data: bytes) -> None: ...
        async def get(self, key: str) -> bytes: ...
        async def list(self, prefix: str) -> list[str]: ...
        async def delete(self, key: str) -> None: ...
    ```
    `LocalArchiveStore` writes to `Settings.archive.local_dir`. Each
    archive is a directory containing `manifest.json` and one or
    more blob files. (The CLI tar+zst step is layered on top.)

    Tests:
    - `test_local_archive_store_put_get`
    - `test_local_archive_store_list`
    - `test_local_archive_store_delete`

90. **`ArchiveManifest` schema with `format_version: int = 1`** —
    `raghub/archive/manifest.py`. Version-pinned from day 1 per R6.
    ```python
    class ArchiveManifest(BaseModel):
        format_version: Literal[1] = 1
        app_version: str
        created_at: datetime
        tenant_ids: list[str]
        entries: list[ArchiveEntry]
        signature: str  # HMAC-SHA256 of the canonical JSON form

    class ArchiveEntry(BaseModel):
        path: str
        sha256: str
        size_bytes: int
        kind: Literal["registry", "manifest", "queue", "feedback",
                      "sessions", "image_store", "embeddings",
                      "metadata"]
    ```
    Bumping `format_version` is a breaking change and requires an
    ADR.

    Tests:
    - `test_manifest_format_version_is_pinned`
    - `test_manifest_signature_verifies`
    - `test_manifest_signature_fails_on_tamper`

91. **`create_snapshot(root, …)` library API** —
    `raghub/archive/snapshot.py`. Walks `root`, captures every
    registered store, builds an `ArchiveManifest`, computes SHA-256
    per file, signs the manifest, and returns a
    `SnapshotResult(manifest, entries)`.

    Bundles:
    - SQLite files: `registry.db`, `sessions.db`, `queue.db`,
      `feedback.db`, `audit.db` (audit added in v0.7.3).
    - JSON registry: `registry.json`.
    - Manifests: every `manifest.json` under `root`.
    - Image store: contents of `Settings.image_store.dir`.
    - Optional embeddings: `embeddings.npy` (re-derivable from
      source when missing).

    Tests:
    - `test_snapshot_collects_all_components`
    - `test_snapshot_computes_sha256`
    - `test_snapshot_signature_verifies`

92. **`restore_snapshot(archive, target, …)` library API** —
    `raghub/archive/snapshot.py`. Reads `manifest.json`, verifies
    HMAC signature, verifies each entry's SHA-256, restores into
    `target`. Refuses to restore if any entry fails verification.

    Tests:
    - `test_restore_writes_all_components`
    - `test_restore_refuses_on_signature_mismatch`
    - `test_restore_refuses_on_sha256_mismatch`

93. **CLI: `raghub backup --output path.tar.zst
    [--include-source] [--include-embeddings] [--tenant <id>]`** —
    `raghub/cli_commands/__init__.py`. The CLI:
    - Calls `create_snapshot(root)`.
    - If `--include-source`, also captures the source documents
      directory.
    - If `--tenant <id>`, scopes the snapshot to that tenant
      (cross-tenant data excluded).
    - If `--include-embeddings`, includes the embeddings file.
      Default `True`.
    - Bundles into a deterministic tar + `manifest.json`, compresses
      with zstd, writes to `--output`.

    Tests:
    - `test_cli_backup_creates_archive`
    - `test_cli_backup_with_tenant_scope`
    - `test_cli_backup_with_source`
    - `test_cli_backup_is_deterministic`

94. **CLI: `raghub restore --input path.tar.zst [--target-dir …]
    [--tenant <id>]`** —
    `raghub/cli_commands/__init__.py`. The CLI:
    - Reads the tar header.
    - Verifies HMAC signature.
    - Verifies each entry's SHA-256.
    - Extracts to `--target-dir` (default `Settings.data_dir`).
    - `--tenant <id>` restores only that tenant's data.

    Tests:
    - `test_cli_restore_round_trip`
    - `test_cli_restore_refuses_on_signature_mismatch`
    - `test_cli_restore_refuses_on_sha256_mismatch`

95. **CLI: `raghub backup verify --input path.tar.zst`** —
    `raghub/cli_commands/__init__.py`. The CLI:
    - Reads `manifest.json` from the archive.
    - Verifies HMAC signature.
    - Verifies each entry's SHA-256.
    - Returns exit code `0` on success, `1` on failure.

    Tests:
    - `test_cli_verify_succeeds_on_valid_archive`
    - `test_cli_verify_fails_on_tampered_archive`

96. **Re-embed option on restore** —
    `raghub/archive/restore.py`. `--re-embed=true` (default `False`)
    causes the restore to drop the embeddings file and re-derive
    embeddings from the source documents. Used when the operator
    upgrades the embedder between backup and restore.

    Tests:
    - `test_restore_with_re_embed_drops_embeddings`
    - `test_restore_without_re_embed_keeps_embeddings`

97. **Plugin registry: `register_archive_store`** —
    `PluginKind.ARCHIVE_STORE` and entry-point
    `group="raghub.archives"`. Allows community adapters for S3 /
    GCS / Azure without changing the format.

    Tests:
    - `test_plugin_registry_archive_store`

## Security review

This release introduces a portable archive format; the security
artefact is `docs/security/threat-models/v0.7.8-backup.md`.

The threat model is mandatory. A cryptographic review of the manifest
format is also required.

### Threat model

| Threat | Mitigation |
|---|---|
| **Backup-file tampering**: an attacker with write access to the archive modifies a chunk's text or metadata, then restores into production. | Per-entry SHA-256 verified before any file is restored; mismatch aborts the restore with a clear error. |
| **Manifest forgery**: an attacker rewrites `manifest.json` to claim a malicious entry has a valid SHA-256. | Manifest is HMAC-SHA256 signed with `RAGHUB_ARCHIVE_SIGNING_KEY`; signature verified before any entry's SHA-256 is consulted. The signing key is required in production; missing key fails closed. |
| **Path traversal in tar extraction**: an attacker crafts a tar containing `../etc/passwd` or absolute paths to overwrite system files. | Tar entries are validated against the target root; any entry whose resolved path escapes the target is rejected; the entire restore aborts. Test asserts `../etc/passwd` is rejected. |
| **Cross-tenant restore**: an attacker with admin role restores a snapshot containing tenant A's data into tenant B's namespace. | `--tenant <id>` scopes both backup and restore; cross-tenant restore requires a separate explicit operator command (`raghub restore --cross-tenant-merge --confirm`), which logs an audit event. |
| **Signing key leakage**: the HMAC key is leaked. | Key rotation API; operator responsibility to rotate `RAGHUB_ARCHIVE_SIGNING_KEY` regularly. |
| **Embedding inversion**: an attacker recovers source text from the embeddings file. | Documented operator responsibility; `--include-embeddings=false` is the safe default; `--re-embed=true` re-derives from source. |
| **Zip-slip analogue for tar**: a tar entry resolves outside the target directory via `..` segments or symlinks. | Entries with `..` segments rejected; symlinks rejected; absolute paths rejected. |
| **Denial of service via huge archive**: an attacker submits a 100 GB archive to exhaust disk. | `--max-archive-size` setting (default 100 GB) enforced at extract time. |
| **TOCTOU on signature check**: the manifest is verified, then the file is read; an attacker swaps the file between steps. | Single transaction-style extraction: signature and SHA-256 verified against the in-memory manifest, then files read; if any file's SHA-256 doesn't match its declared value, the restore aborts and the partial extract is rolled back. |
| **Plaintext PII in backup**: the archive contains unredacted feedback comments. | Re-embed option redacts feedback comments at restore time when `--redact-feedback=true` is set; documented operator workflow. |

### Mitigations accepted

- Per-entry SHA-256 verification.
- HMAC-SHA256 signed manifest.
- Path traversal blocked.
- Cross-tenant restore explicitly opt-in.
- Required signing key in production.

### Out-of-scope

- Encryption at rest: deferred. The operator can layer encryption
  (e.g. `gpg`, `age`) on top of the archive; documented in the
  adapter reference.

### Cryptographic review required

The manifest format and HMAC scheme require an external review.
Reviewer confirms:

- HMAC-SHA256 is appropriate.
- Key length ≥ 32 bytes (matches `RAGHUB_ARCHIVE_SIGNING_KEY`
  minimum from v0.7.0).
- No malleability concerns in the canonical JSON form used for
  signing.
- SHA-256 is sufficient for the entry fingerprints.

The sign-off artefact is
`docs/security/external-reviews/v0.7.8-backup-crypto-signoff.md`.
