# v0.8.0 — Tests, docs, API surface, hygiene

## Theme

Stabilisation release. Every quality gate green; full documentation
set; the public API surface is declared and tracked but **not
frozen**. Hygiene pass: dead code removed; duplicate code
consolidated; small cleanups. This is the first release candidate
for `v1.0.0` once field validation confirms stability (per the
"freeze later, when stable" decision).

## Breaking changes (R4 — no shims, no aliases, no deprecation)

- `CoverageConfig` now requires the new coverage gates:
  - CI: **≥ 90 %**
  - Release: **≥ 95 %**
- `tools/check_function_length.py` runs in CI; any function > 40
  LOC fails the build.
- `tools/check_naming.py` runs in CI; any forbidden name or
  `_`-prefix identifier fails the build.
- The `docs/reference/public-api.md` file becomes the canonical
  declaration of every public symbol; missing symbols here are
  treated as documentation bugs.

## Prerequisites

- `v0.7.8` is the current published release.

103. **Fuzz tests** — `tests/fuzz/`:
     - `test_parsers_fuzz.py` — Hypothesis strategies for

       unicode inputs.
     - `test_vector_stores_fuzz.py` — random insert/delete/search

     - `test_json_loaders_fuzz.py` — malformed JSON, deep
       nesting, unicode edge cases.
     - `test_migrations_fuzz.py` — random schema combinations.
     Tests assert no crashes and no exception leakage beyond the

104. **Property-based tests (Hypothesis) with stated invariants** —
     `tests/properties/`:
     - `test_rrf_fusion.py` — invariant: `fuse(a, b) == fuse(b, a)`
       (commutativity up to score normalisation); `fuse(a, a) == a`.
     - `test_bm25_scoring.py` — invariant: identical documents get
       identical scores; an empty query returns empty.
     - `test_token_budget.py` — invariant: prompt never exceeds
       `max_tokens`; system prompt always retained.
     - `test_deterministic_id.py` — invariant: same inputs →
       same id.
     - `test_manifest_round_trip.py` — invariant: `loads(dumps(m)) == m`.
     - `test_okf_round_trip.py` — invariant: same for OKF.
     - `test_sliding_window.py` — invariant: total tokens never
       exceeds `max_tokens`; the most recent turn is preserved.
     - `test_isolation_routing.py` — invariant: tenant A never
       sees tenant B's chunks regardless of strategy.
     - `test_rate_limit_bucket.py` — invariant: refill rate
       matches `rps`; burst never exceeds `burst + 1`.
     - `test_feedback_scorer.py` — invariant: no feedback ⇒
       identity; positive feedback strictly improves rank.

## Security review

This release is the stabilisation gate; the security artefact is
`docs/security/v0.8.0-consolidated-threat-model.md`.

### Consolidated threat model

The per-release threat models (v0.7.0 through v0.7.8) are
consolidated into one document that:

- Lists every threat from every release in one table.
- Marks each threat as Accepted, Mitigated-but-monitored, or
  Deferred.
- Cross-references the test that verifies the mitigation.
- Cross-references the code change that introduced the surface.

The consolidated document is the canonical security artefact for
v0.8.0 and is the input to the v1.0.0 release-candidate review.

## What comes next (post-v0.8.0)

After field validation of v0.8.0, the next step is to consider
declaring a **public API freeze** at `v1.0.0`. The freeze decision
is "later, when stable" per the project's policy; the trigger is
field validation confirming the public surface has held for at
least one minor cycle.

Until then:

- Additive changes to the public surface are permitted without an
  ADR.
- Breaking changes always require an ADR + SemVer bump.
- The `docs/reference/public-api.md` snapshot is updated every
  release.
