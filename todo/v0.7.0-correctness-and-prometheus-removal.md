# v0.7.0 — Correctness, Prometheus removal, Langfuse core

## Theme

Fix all known correctness bugs surfaced in the v0.6.0 audit; remove
Prometheus entirely (no `[observability]` extra — Prometheus is not an
adapter in this codebase); promote Langfuse to a core dependency.
This release is **non-negotiable**: every later release assumes it has
landed.

## Breaking changes (R4 — no shims, no aliases, no deprecation)

- `raghub.Prometheus` re-export deleted from `raghub.telemetry`.
- `raghub.PrometheusMetrics`, `raghub.NullMetrics`,
  `raghub.DEFAULT_METRICS_REGISTRY`, `raghub.set_active_metrics`,
  `raghub.record_rerank_latency`, `raghub.record_long_context`,
  `raghub.generate_latest` deleted.
- `/metrics` FastAPI route deleted.
- `prometheus-client` removed from `pyproject.toml`. It is **not** an
  optional extra; it is gone.
- `langfuse` promoted from `[langfuse]` extra to a core dependency.
  The `[langfuse]` extra is kept as a no-op for one release and
  removed in v0.7.1.
- `SqliteStore.hybrid_search` renamed to `search_hybrid`; raises
  `ConfigurationError` when BM25 is unavailable.
- `RouteGroup` split into `HealthRouter`, `AuthRouter`,
  `DocumentRouter`, `QueryRouter`, `AgentRouter`, `AdminRouter`;
  internal `_`-prefix methods renamed to public or `__dunder__`.
- `Agent.iterate` decomposed into `__check_budget`,
  `__build_prompt`, `__dispatch`, `__render_final`; signatures
  may change.

## Prerequisites

- `v0.6.0` is the current published release.

## Security review

This release touches observability and dep surface; the security
artefact is `docs/security/threat-models/v0.7.0-no-prometheus.md`.

### Threat model

| Threat | Mitigation |
|---|---|
| `/metrics` route previously exposed internal counters (timing, error rates, tenant activity) over HTTP; any caller on the network could scrape them and use them for fingerprinting or capacity planning against the operator. | Route deleted; no replacement endpoint ships in this release. |
| `prometheus-client` transitive dependencies (e.g. `twisted`) widened the supply-chain attack surface. | Dependency deleted; lockfile updated. |
| Hot-path record helpers previously wrote to a global in-process registry; cross-tenant data could in principle leak via metric labels if a label used tenant id and the registry was shared. | Labels now flow through Langfuse `score`, which carries its own tenant context; no global in-process registry remains. |
| `langfuse` promotion to core dep widens the supply-chain attack surface for users who never set `LANGFUSE_*` env vars. | Langfuse is lazy-imported inside `LangfuseTelemetryProvider`; if the env vars are absent, the provider returns `NoOpTelemetry` and never imports the SDK. |

### Mitigations accepted

- `/metrics` route deleted; no replacement endpoint.
- `prometheus-client` removed from `pyproject.toml` and lockfile.
- `langfuse` lazy-imported; no eager import at package init.
- Langfuse `score` calls include the tenant id as metadata, so
  per-tenant observability is preserved.

### Out-of-scope (handled in later releases)

- Threat model for tenant identification spoofing: v0.7.3.
- Threat model for queue job poisoning: v0.7.4.
- Threat model for cross-tenant isolation: v0.7.6.
- Threat model for backup-file tampering: v0.7.8.
