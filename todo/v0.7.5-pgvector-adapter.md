# v0.7.5 — pgvector adapter

## Theme

Land the first first-class vector-store adapter: **pgvector**. This
release unblocks the v0.7.6 multi-tenant isolation tiers
(schema-per-tenant and database-per-tenant both require a Postgres
backend). pgvector is the only first-class adapter in this release;
the Qdrant / FAISS / Chroma / Milvus story stays as an entry-point
contract per the v0.7.1 decision.

## Breaking changes (R4 — no shims, no aliases, no deprecation)

- `Store` Protocol becomes the canonical contract; concrete
  implementations must satisfy it without exception. Any prior
  duck-typed `Store` consumers must migrate.
- `raghub/store.py` (the file) is split into:
  - `raghub/store/protocol.py` — `Store` Protocol
  - `raghub/store/memory.py` — `MemoryStore`
  - `raghub/store/sqlite.py` — `SqliteStore`
  - `raghub/store/pgvector.py` — `PgVectorStore` (new)
- Any importer of `from raghub.store import Store` continues to work
  via re-export; any importer of `from raghub.store import MemoryStore`
  must migrate to `from raghub.store.memory import MemoryStore`.

## Prerequisites

- `v0.7.4` is the current published release.

## Atomic items

62. **`PgVectorStore` skeleton + `[pgvector]` extra** —
    `raghub/store/pgvector.py`. The skeleton defines the class and
    the optional `[pgvector]` extra in `pyproject.toml` declares
    `asyncpg>=0.27,<1`. The class is registered in `PluginRegistry`
    as `PluginKind.VECTOR_STORE, "pgvector"`.

    Tests:
    - `test_pgvector_import_outside_extra_raises_missing_dep_error`
    - `test_pgvector_protocol_conformance`

63. **Schema + index creation (IVFFlat / HNSW)** — `create_collection`.
    Schema:
    ```sql
    CREATE TABLE IF NOT EXISTS raghub_chunks (
        id TEXT PRIMARY KEY,
        document_id TEXT NOT NULL,
        ordinal INTEGER NOT NULL,
        text TEXT NOT NULL,
        metadata JSONB NOT NULL DEFAULT '{}'::jsonb,
        embedding VECTOR(N) NOT NULL,
        tenant_id TEXT,
        created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
        updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
    );
    CREATE INDEX IF NOT EXISTS raghub_chunks_tenant_id
        ON raghub_chunks (tenant_id);
    CREATE INDEX IF NOT EXISTS raghub_chunks_document_id
        ON raghub_chunks (document_id);
    ```
    Index creation uses the operator-supplied `distance_metric`
    (`cosine` / `l2` / `inner_product`) and `index_type`
    (`ivfflat` / `hnsw`). Default: `cosine` + `hnsw`.

    Tests:
    - `test_pgvector_create_collection_with_hnsw`
    - `test_pgvector_create_collection_with_ivfflat`
    - `test_pgvector_create_collection_with_l2`
    - `test_pgvector_create_collection_idempotent`

64. **Insert / upsert / delete / search** — operations on
    `PgVectorStore`:
    - `insert(chunks: Sequence[Chunk], vectors: Sequence[Sequence[float]]) -> int`
    - `upsert(chunks: Sequence[Chunk], vectors: Sequence[Sequence[float]]) -> int`
    - `delete(chunk_id: str) -> None`
    - `delete_document(document_id: str) -> None`
    - `search(query_vector, top_k, metadata_filter=None) -> list[Hit]`

    All queries parameterised; `metadata_filter` rendered through a
    safe parameter binder (no string interpolation).

    Tests:
    - `test_pgvector_insert_returns_count`
    - `test_pgvector_upsert_overwrites`
    - `test_pgvector_delete_by_id`
    - `test_pgvector_delete_document`
    - `test_pgvector_search_cosine`
    - `test_pgvector_search_metadata_filter`

65. **Hybrid search: Postgres FTS + RRF** — `search_hybrid`. A
    `tsvector` column is generated from `text`; BM25-equivalent
    scoring via `ts_rank_cd`; results fused with the existing
    `Retrieval.fusion.rrf` (k=60).

    Schema addition:
    ```sql
    ALTER TABLE raghub_chunks
        ADD COLUMN text_search tsvector
        GENERATED ALWAYS AS (to_tsvector('english', text)) STORED;
    CREATE INDEX IF NOT EXISTS raghub_chunks_text_search
        ON raghub_chunks USING GIN (text_search);
    ```

    Tests:
    - `test_pgvector_hybrid_search_returns_fused_results`
    - `test_pgvector_hybrid_search_rrf_ranking`

66. **`optimize` / `health`** — maintenance ops.
    - `optimize()` — runs `VACUUM ANALYZE raghub_chunks` and
      rebuilds the HNSW/IVFFlat index if the row count drifted by
      more than 20 % since the last optimisation.
    - `health()` — returns `{status, backend, chunks, index_size,
      last_optimized_at}`.

    Tests:
    - `test_pgvector_optimize_rebuilds_index`
    - `test_pgvector_optimize_noop_when_drift_below_threshold`
    - `test_pgvector_health_returns_state`

67. **RLS hooks: `SET LOCAL app.current_user_id`,
    `app.current_tenant_id`** — wired into every connection
    acquisition. Each connection runs:
    ```sql
    SET LOCAL app.current_user_id = $1;
    SET LOCAL app.current_tenant_id = $2;
    ```
    with values from the `TenantResolver` (via the request context).
    Row-level security policies are documented in the adapter
    reference; the policies themselves are added in the v0.7.6
    multi-tenant isolation release.

    Tests:
    - `test_pgvector_sets_user_and_tenant_per_connection`
    - `test_pgvector_uses_correct_connection_per_request`
    - `test_pgvector_resets_session_vars_on_release`

68. **Migration CLI: `raghub migrate pgvector --dsn …`** —
    `raghub/migrate.py`. New sub-command:
    - `raghub migrate pgvector --dsn postgresql://…` creates the
      schema and indexes.
    - `--drop-existing` flag drops the tables first (default `False`).
    - `--vector-dim N` declares the embedding dimension (default
      from `Settings.embedding_dim`).

    Tests:
    - `test_migrate_pgvector_creates_schema`
    - `test_migrate_pgvector_drop_existing`
    - `test_migrate_pgvector_vector_dim_default`

## Security review

This release introduces a new SQL surface; the security artefact is
`docs/security/threat-models/v0.7.5-pgvector.md`.

### Threat model

| Threat | Mitigation |
|---|---|
| **SQL injection via `metadata_filter`**: a caller passes `{"company": "x' OR 1=1--"}` and the filter renders to `WHERE metadata->>'company' = 'x' OR 1=1--'`, bypassing tenant filter. | `metadata_filter` rendered through a typed binder that quotes values and uses `?` placeholders; values are bound parameters, never interpolated. Property test injects adversarial payloads and asserts they are escaped. |
| **Search-path attack**: the connection's `search_path` is mutable; an attacker who gains SQL execution can read from other schemas. | Connection acquisition pins `search_path` to a per-tenant or per-database path (set in v0.7.6); RLS policies added in v0.7.6. |
| **Connection-string leakage**: the DSN is logged on error or stored in telemetry. | `RedactingTelemetry` redacts keys containing `dsn`, `password`, `connection_string`. DSN never appears in `repr()`. |
| **Privilege escalation via `SET ROLE`**: a malicious user issues `SET ROLE app_admin` mid-session. | The Postgres role used by `PgVectorStore` has only the minimum required grants (`SELECT`, `INSERT`, `UPDATE`, `DELETE` on `raghub_chunks`, `USAGE` on the schema); `SET ROLE` is denied by `GRANT`. Documented in the adapter reference. |
| **Embedding inversion**: an attacker with read access to the `embedding` column recovers source text via gradient inversion. | Documented risk; the threat model calls out operator responsibility for column-level encryption at rest (`pgcrypto`) and access control. |
| **Index poisoning**: an attacker inserts adversarial vectors that degrade HNSW/IVFFlat recall. | `optimize()` rebuilds the index; per-tenant rebuild available; documented. |
| **Cross-tenant query**: an attacker without `tenant_id` set on the session reads another tenant's chunks. | `SET LOCAL app.current_tenant_id` enforced at every connection acquisition; RLS policies deny cross-tenant reads (policies land in v0.7.6). |

### Mitigations accepted

- Parameterised SQL throughout.
- Typed metadata filter binder.
- `RedactingTelemetry` for DSN.
- `SET LOCAL` for user and tenant.
- Documented operator responsibilities (pgcrypto, grants).

### Out-of-scope (handled in later releases)

- RLS policies themselves: v0.7.6.
- Schema-per-tenant and database-per-tenant routing on `search_path`:
  v0.7.6.
- Backup of `raghub_chunks`: v0.7.8.
