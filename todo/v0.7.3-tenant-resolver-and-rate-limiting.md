# v0.7.3 — TenantResolver + per-tenant rate limiting

## Theme

Introduce the `TenantResolver` abstraction early so it can be reused
by every later multi-tenant feature (queue, isolation, feedback,
backup). Add per-tenant rate limiting with global defaults. Wire an
audit log so every rate-limit decision is observable through Langfuse.

This is the first release in the v0.7.x series that introduces
new behaviour; it depends on the type discipline of v0.7.2 to keep
the new boundaries typed.

## Breaking changes (R4 — no shims, no aliases, no deprecation)

- `TokenBucket` keyed by string is replaced by `TokenBucket` keyed
  by `(tenant_id, route)` tuple. Any direct construction of
  `TokenBucket("ip", rate, burst)` must migrate to
  `TokenBucket((tenant_id, route), rate, burst)`.
- New `RateLimitConfig` block in `Settings`; existing rate-limit
  env vars move under this block.
- New `RateLimiter` Protocol; the concrete
  `RateLimiterMiddleware` becomes a thin wrapper around it.
- New `AuditLog` Protocol and `SqliteAuditLog` implementation.
- 429 responses now carry `Retry-After`, `X-RateLimit-Remaining`,
  `X-RateLimit-Limit` headers — clients that parsed body-only 429
  responses must update.

## Prerequisites

- `v0.7.2` is the current published release.
- `TenantResolver` is introduced **here**, ahead of the v0.7.6
  isolation release, so that rate limiting and every later feature
  share one resolution contract.

## Atomic items

45. **`TenantResolver` Protocol + default impl** —
    `raghub/tenants/__init__.py`. Define:
    ```python
    class TenantResolver(Protocol):
        def resolve(self, request: RequestLike) -> TenantId | None: ...
    ```
    Default implementation `HeaderTenantResolver` reads
    `X-Tenant-ID`; `JwtClaimTenantResolver` reads the `tenant_id`
    claim; `CompositeTenantResolver` prefers the JWT claim and falls
    back to the header. The default registration is
    `CompositeTenantResolver`.

    Tests:
    - `test_tenant_resolver_header_only`
    - `test_tenant_resolver_jwt_only`
    - `test_tenant_resolver_jwt_wins_over_header`
    - `test_tenant_resolver_missing_returns_none`
    - `test_tenant_resolver_invalid_tenant_id_raises_authorization_error`

46. **`RateLimitConfig` block in `config.py`** — adds:
    - `per_tenant_rps: float = 10.0`
    - `per_tenant_burst: float = 20.0`
    - `per_user_rps: float = 5.0`
    - `per_user_burst: float = 10.0`
    - `exempt_tenants: list[str] = []`
    - `backend: Literal["memory", "sqlite"] = "memory"`
    - `audit_log_enabled: bool = True`

    Env-var parsing helpers added to `raghub/config.py`.
    Tests:
    - `test_config_validation.py::test_rate_limit_config_defaults`
    - `test_config_validation.py::test_rate_limit_config_env_override`

47. **`TokenBucket` keyed by `(tenant_id, route)`** —
    `raghub/api_ratelimit/__init__.py`. Replace the string key with
    a tuple key; update the in-process map; update eviction policy
    to be per-tenant LRU.

    Tests:
    - `test_token_bucket_per_tenant_isolation`
    - `test_token_bucket_refill_correctness`
    - `test_token_bucket_burst_then_refill`
    - `test_token_bucket_eviction_under_load`

48. **Wire `TenantResolver` into the rate-limit middleware** —
    `raghub/api.py`. The middleware reads the tenant at request time
    via `TenantResolver.resolve(request)` and passes the
    `(tenant_id, route)` key to the bucket. Missing tenant → no rate
    limit applied at the tenant tier; per-IP limit still applies.

    Tests:
    - `test_rate_limit_uses_tenant_id_when_present`
    - `test_rate_limit_falls_back_to_ip_when_tenant_missing`
    - `test_rate_limit_exempt_tenants_are_bypassed`

49. **`sqlite` rate-limit backend** — `raghub/api_ratelimit/sqlite.py`.
    New `SqliteRateLimiter` backed by `aiosqlite`. State persists
    across process restarts. Same `RateLimiter` Protocol; swap via
    `Settings.rate_limit.backend`.

    Tests:
    - `test_sqlite_rate_limiter_basic`
    - `test_sqlite_rate_limiter_persistence_across_instances`

50. **429 response with `Retry-After`, `X-RateLimit-Remaining`,
    `X-RateLimit-Limit`** — `raghub/api_response/__init__.py`
    `RateLimited` builder. The middleware sets these headers on the
    429 response.

    Tests:
    - `test_429_headers_present`
    - `test_429_retry_after_value`
    - `test_429_remaining_value_decreases`

51. **Audit log on every 429** — `raghub/audit/__init__.py`. New
    `AuditLog` Protocol; `SqliteAuditLog` implementation; `NoOpAuditLog`
    fallback. Audit entries are signed with HMAC-SHA256 using
    `RAGHUB_AUDIT_SECRET` (fail-closed if unset in production).

    Fields: `tenant_id`, `user_id`, `route`, `decision` (allow/deny),
    `retry_after_seconds`, `timestamp`, `signature`.

    Tests:
    - `test_audit_log_records_429`
    - `test_audit_log_signature_verifies`
    - `test_audit_log_rejects_tampered_entry`
    - `test_audit_log_noop_when_disabled`

52. **Admin endpoint `GET /v1/admin/tenants/{id}/rate-limit`** — new
    `AdminRouter` endpoint returning current per-tenant bucket state
    (rps used, rps remaining, last refill). Authenticated via
    `AuthService.admin` dependency.

    Tests:
    - `test_admin_rate_limit_endpoint_returns_state`
    - `test_admin_rate_limit_endpoint_requires_admin`
    - `test_admin_rate_limit_endpoint_unknown_tenant_404`

## Security review

This release introduces the first tenant-bound runtime decision
point; the security artefact is
`docs/security/threat-models/v0.7.3-rate-limiting.md`.

### Threat model

| Threat | Mitigation |
|---|---|
| **Tenant-id spoofing via `X-Tenant-ID` header**: an attacker sends `X-Tenant-ID: <victim-tenant>` to consume the victim's rate-limit budget and cause a denial of service. | `CompositeTenantResolver` always prefers the JWT claim over the header; the header is used only when the JWT has no `tenant_id` claim. |
| **Header injection via CRLF in `X-Tenant-ID`**: an attacker sends `X-Tenant-ID: foo\r\nSet-Cookie: ...` to inject headers. | `TenantResolver` validates the tenant id against a strict regex (`^[a-z][a-z0-9_-]{2,63}$`); invalid values raise `AuthorizationError`. |
| **Audit-log tampering**: an attacker with write access to the SQLite audit DB rewrites history to hide abuse. | HMAC-SHA256 signature per entry using `RAGHUB_AUDIT_SECRET`; verification fails closed. |
| **Audit secret missing in production**: a misconfigured deployment silently loses audit coverage. | `RAGHUB_AUDIT_SECRET` is required when `environment == "production"`; missing secret raises `ConfigurationError` at startup. |
| **Bucket state DoS**: an attacker drives the bucket state to unbounded growth across many tenants. | Per-tenant LRU eviction; cap on total buckets (`MAX_TRACKED_TENANTS=10_000`); eviction tested. |
| **Token-bucket key collision**: a code bug lets tenant A's bucket be reused as tenant B's bucket. | Tuple key `(tenant_id, route)` enforced at type level; `TypedDict` return shape; property test asserts no collision. |
| **Exempt-tenant list bypass**: an operator typos a tenant id and the bypass silently fails. | Startup validation: each `exempt_tenants` entry is matched against the known tenant set; unknown entries raise `ConfigurationError`. |

### Mitigations accepted

- JWT-over-header precedence.
- Strict regex on tenant id.
- HMAC-SHA256 signed audit log.
- Required `RAGHUB_AUDIT_SECRET` in production.
- LRU eviction with cap.
- Startup validation of the exempt list.

### Out-of-scope

- Tenant identification for **storage** routing (schema-per-tenant,
  database-per-tenant): v0.7.6.
- Tenant identification for **queue** routing: v0.7.4 (queue jobs
  carry `tenant_id` from v0.7.5 onwards; v0.7.4 introduces the
  column but does not route on it).
- Feedback tenant isolation: v0.7.7.
- Backup per-tenant scope: v0.7.8.
